# 10 — 🔴 용량 예산 (1.44MB) · 개발 최적화 규칙 [최우선]

> **이 규칙이 모든 규칙을 이긴다.** 게임성·기능·미관과 충돌하면 **용량이 우선**한다.
> 콘테스트 하드 캡: **최종 standalone .exe ≤ 1,474,560 바이트** (3.5" 플로피 용량). 초과 = 실격.

## 0. 단일 수치
```
HARD_CAP      = 1,474,560 bytes   (1.44MB)
TARGET        =    65,536 bytes   (64KB,  내부 목표 — 압축 없이도 무여유 통과)
WARN_AT       =    49,152 bytes   (75% of target)   → 노란불
HARD_WARN_AT  = 1,179,648 bytes   (80% of cap)      → 빨간불, 즉시 감축
```
전부 절차생성이므로 정상 개발 시 수십 KB. **TARGET(64KB)를 1차 방어선**으로 삼고, 거기서 멀어지면 원인을 즉시 규명한다.

## 1. 측정 (매 빌드 필수)
- `build.bat`은 빌드 후 **exe 바이트 수 + HARD_CAP 대비 % + TARGET 대비 %**를 항상 출력한다.
- `size-guardian` 에이전트 / `/size-check` 가 측정·판정·이력 기록(`.claude/memory/size-history.md`).
- **판정:**
  | 상태 | 조건 | 조치 |
  |---|---|---|
  | 🟢 GREEN | < WARN_AT | 진행 |
  | 🟡 YELLOW | WARN_AT ~ TARGET | 주의, 신규 기능 size 추정 필수 |
  | 🟠 ORANGE | TARGET ~ HARD_WARN_AT | 감축 작업 우선순위 ↑ |
  | 🔴 RED | ≥ HARD_WARN_AT | **신규 기능 동결**, 감축 전까지 머지 금지 |
  | ⛔ FAIL | > HARD_CAP | **빌드 거부 / PR 차단** |

## 2. 게이트 (강제)
- **빌드 훅** `size-budget-check.ps1` (PostToolUse/Stop): exe 측정 → FAIL이면 에러로 차단, RED면 경고.
- **코드리뷰**(`code-reviewer-game`)·**용량감시**(`size-guardian`)는 모든 변경에서 `Δsize`를 보고(00-core LAW 4).
- **머지 금지 조건:** FAIL 상태이거나, 단일 기능이 예산을 정당화 없이 초과.

## 3. 기능별 용량 예산 (가이드, TARGET 64KB 분배)
| 영역 | 예산 |
|---|---|
| 엔진 골격(창/GL/루프/입력/수학/RNG) | ~8KB |
| 렌더(즉시모드·글로우·폰트·파티클) | ~10KB |
| 던전 생성 + 충돌 | ~6KB |
| 적·보스 AI | ~10KB |
| 모듈/강화 시스템 | ~6KB |
| 사운드(신스·믹서) | ~8KB |
| UI/HUD/상태머신 | ~6KB |
| 예비 | ~10KB |
> 어떤 기능이 예산을 넘으면 PM에 에스컬레이션 → 범위 조정 or 다른 영역 감축.

## 4. 최적화 기법 (개발 표준)
**컴파일/링크**
- `cl /O1 /Os /GS- /Gy`  (크기 우선 최적화, 스택쿠키 제거, 함수 단위 링크)
- `link /NODEFAULTLIB /OPT:REF /OPT:ICF`  (CRT 제거, 데드코드/동일코드 폴딩)
- x64 고정(no-CRT float 헬퍼 회피). 명시 라이브러리만 링크.

**코드/자산**
- 에셋 파일 금지 → 텍스처는 절차/셰이더-less, 맵은 시드, 폰트는 3×5 비트맵을 코드에 인코딩.
- 사운드는 샘플 금지 → 실시간 신스(파형 함수 + 엔벨로프).
- 문자열 최소화(긴 리터럴·디버그 텍스트 금지). 포맷 함수(printf류) 금지 → 자작 정수→글리프.
- 룩업테이블은 시작 시 계산 생성(데이터로 박지 말 것). 단, 코드가 테이블보다 크면 역으로.
- 중복 로직 통합(원-원/원-타일 충돌, 도형 드로우 헬퍼 1곳).
- `float`/`double` 혼용 최소화, 상수는 `f` 접미사.

**최종 압축(선택, 미니멀이면 불필요)**
- UPX 또는 **Crinkler**(no-CRT 전용). ⚠️ 콘테스트 규칙 "압축 해제 후 ≤ cap" 해석 주의 → **압축 없이도 cap 안에** 드는 것을 1차 목표로(어느 해석이든 안전).

## 5. 규율
- **신규 코드 작성 전 size 영향 추정 → 작성 후 실측 → 이력 기록.**
- size 회귀(직전 빌드 대비 급증)는 즉시 원인 규명(보통: 큰 정적배열, 부주의한 CRT 인입, 문자열, float 변환 헬퍼).
- "나중에 줄이자"는 금지. **상시 작게** 유지가 비용이 가장 적다.
- 큰 정적 버퍼는 `.bss`(0초기화)로 → 파일 크기에 미포함. **초기화된 큰 배열을 피하라**(파일에 박힘).
