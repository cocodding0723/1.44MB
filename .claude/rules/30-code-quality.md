# 30 — 코드 품질 (Karpathy verify-loop 적용)

## 4원칙
1. **작성 전 사고(Think Before Coding).** 가정을 명시하고, 해석이 여러 개면 조용히 고르지 말고 드러낸다. 스펙(`DESIGN.md`)과 충돌하면 멈추고 보고.
2. **단순함 우선(Simplicity First).** 최소 코드. 단일 사용처에 추상화 금지. 투기적 일반화 금지. (용량 규칙과 동일 방향 — 단순할수록 작다.)
3. **외과적 변경(Surgical Changes).** 바뀐 모든 줄은 요청에 직접 추적 가능해야 한다. 인접 코드 임의 리팩터 금지. 주변 코드 스타일을 따른다.
4. **목표 주도 실행 / 검증 루프(Goal-Driven, Verify-Loop).** 성공 기준을 먼저 정의하고 검증될 때까지 반복.

## 검증 루프 (개발 표준)
태스크를 검증 가능 형태로 변환:
- "이동 구현" → "WASD로 8방향 이동 + 벽 충돌, 시드 고정 시 동일 경로" 를 만족할 때까지
- "버그 수정" → "버그를 재현하는 테스트/시나리오 작성 → 통과시킨다"

계획 포맷:
```
1. [단계] → verify: [확인 방법]
2. [단계] → verify: [확인 방법]
```
강한 성공 기준은 에이전트가 독립적으로 루프 돌게 한다. "동작하게 해"는 금지.

## 게임 특화
- **결정론:** 모든 랜덤은 시드 기반(`xorshift`). 같은 시드 = 같은 결과(QA 재현성).
- **고정 타임스텝:** sim 120Hz 고정. 프레임률과 게임 로직 분리.
- **juice는 기능이다:** 셰이크·히트스톱·파티클은 "있으면 좋은" 게 아니라 손맛의 핵심(검사기준서에 포함).
- **상수는 한곳(`DESIGN.md §21` ↔ 코드 상수 블록):** 매직넘버 산재 금지, 튜닝 1곳.
